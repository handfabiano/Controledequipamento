# Migração de banco

1. Leia `docs/BANCO_DE_DADOS.md` e as duas definições da tabela em `schema.sql` e `schema.pg.sql`.
2. **Tabela/índice novo**: adicione nos DOIS arquivos com `CREATE ... IF NOT EXISTS`.
   | SQLite | Postgres |
   |---|---|
   | `INTEGER PRIMARY KEY AUTOINCREMENT` | `INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` |
   | `DATETIME DEFAULT CURRENT_TIMESTAMP` | `TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP` |
   Booleano = `INTEGER` 0/1. Toda tabela precisa de `id`. Sem `;` em strings/comentários (o `init.js` faz `split(';')`).
3. **Coluna nova em tabela existente**: `CREATE TABLE IF NOT EXISTS` não basta. Adicione em `init.js` uma etapa idempotente após o schema:
   - Postgres: `ALTER TABLE t ADD COLUMN IF NOT EXISTS c TIPO DEFAULT x`.
   - SQLite: não tem `IF NOT EXISTS` para coluna → consultar `PRAGMA table_info(t)` e só então `ALTER TABLE ... ADD COLUMN`.
   Coloque também a coluna no `CREATE TABLE` para bancos novos. Constraints `CHECK` novas em tabela existente exigem recriar tabela no SQLite — evite ou planeje.
4. Atualize seed (`insertInitialData`) se necessário e os controllers/validators que usam a coluna.
5. **Testar**: apague `server/database/equipamentos.db` e suba (banco novo); depois suba sobre um banco criado com o schema ANTIGO (migração). Se possível teste também com `DATABASE_URL` de Postgres descartável.
6. Nunca rode DDL em banco de produção sem confirmação explícita; descreva ao usuário o passo a executar.
7. Atualize `docs/BANCO_DE_DADOS.md`.
